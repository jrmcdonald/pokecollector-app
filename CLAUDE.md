# CLAUDE.md

Context for Claude Code sessions working on this repo.

## What this repo is

A personal iOS app (Expo / React Native) for a self-hosted
[PokeCollector](https://github.com/Git-Romer/pokecollector), which runs as a
Home Assistant addon from `jrmcdonald/ha-addons`. It talks to upstream's REST
API, unmodified, through Cloudflare Access. Read `docs/PLAN.md` before
starting work and `docs/DECISIONS.md` before changing an approach.

## Expo has changed — do not trust your training data

This is Expo SDK 57 (React Native 0.86, TypeScript 6). APIs you remember may be
renamed or gone. Check the installed package's types in `node_modules`, or the
versioned docs at `https://docs.expo.dev/versions/v57.0.0/`.

## Commands

```bash
npm start                     # Metro for the dev client (the normal loop)
npm run start:go              # Metro for Expo Go (screens without native modules only)
npm run lint                  # expo lint
npm run typecheck             # tsc --noEmit
npm run format                # prettier --write .
npm test                      # jest
npm run generate:api          # regenerate src/api/generated.ts from openapi/
EXPO_OFFLINE=1 npx expo install <pkg>   # add a dependency at the SDK's version
```

Run lint, typecheck, format check and tests before declaring anything done. CI
runs the same, plus a check that `src/api/generated.ts` matches the spec.

`EXPO_OFFLINE=1` matters in Claude Code on the web: the network policy blocks
`api.expo.dev`, and without it `expo install` fails. Offline, it uses the
version map bundled in the `expo` package, which is what it should use anyway.

## Layout

- `src/app/` — Expo Router routes only. Every file is a screen.
- `src/api/` — the only code that talks to the server: `client.ts` (auth,
  Access, error mapping), `endpoints.ts`, `schemas.ts` (zod), `generated.ts`
  (never edit by hand).
- `src/auth/` — Keychain storage for the server and credentials.
- `src/session/` — the signed-in session and TanStack Query setup.
- `src/components/`, `src/hooks/`, `src/theme/`, `src/utils/`.
- `openapi/` — upstream's spec, one file per pinned upstream version.
  `scripts/export-openapi.sh <version>` exports a new one.

## Rules

- TypeScript strict, no `any`. Response types come from `generated.ts`; zod
  validates the fields the app depends on, with loose objects so new upstream
  fields never break it.
- Screens never call `fetch`. Everything goes through `src/api` and hooks.
- **Never commit** a service token, username or password, and never build a
  server URL into the app's code or config. Nothing secret goes in
  `app.config.ts` or `.env`: the server and credentials are entered on the
  phone and live in the Keychain. (Hostnames in the docs are fine; they are in
  public DNS anyway.)
- Be frugal with requests. The backend allows 60 a minute per client IP, and
  every client behind the Cloudflare tunnel shares one IP. Prefer long
  `staleTime`s and the persisted cache, never per-tile requests, and load card
  images from the TCGdex URLs the API returns.
- `ios/` is generated by `expo prebuild` and gitignored. Configure native
  behaviour in `app.config.ts` and config plugins.
- **Native changes cost a CI build and an AltStore reinstall.** A new native
  dependency, an SDK bump or an `app.config.ts` change means running the
  `iOS build` workflow. Say so clearly in the commit message. Prefer
  JavaScript-only libraries and Expo's own modules.
- Don't change the bundle IDs in `app.config.ts`: a free Apple ID can register
  only ten App IDs a week.
- Update `docs/API.md` when the app starts using a new endpoint and
  `docs/DECISIONS.md` for notable choices.
